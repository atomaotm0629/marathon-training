# 京都マラソン2027 に向けたトレーニング

2027年2月21日（日）の **京都マラソン2027** を完走するための、
トレーニング計画のドキュメントと、練習を記録するローカル完結型の
記録アプリ（`tracker/`）で構成された個人プロジェクトです。

---

## 大会の基本情報

| 項目 | 内容 |
|---|---|
| 大会 | 京都マラソン2027（第16回） |
| 日程 | **2027年2月21日（日）** |
| コース | 西京極総合運動公園スタート → 平安神宮フィニッシュ |
| 制限時間 | **6時間**（関門は8か所） |
| 高低差 | 約75 m。最高地点はスタートから16〜18 km 付近 |
| 定員 | マラソン10,640人（一般枠） |
| 参加料 | 市内 18,500円／市外 19,500円 |

**制限時間6時間は、大阪マラソン・神戸マラソン（7時間）より1時間短い。**
単純平均で **8分32秒/km** を切り続ける必要があり、給水・トイレ・渋滞のロスを
考えると、実質は **8分00秒/km 前後で押していける走力** が最低ラインです。
「歩いてもゴールできる大会」ではない、という前提で計画を立てます。

詳細は [01-race.md](docs/01-race.md) を参照。

## 計画の全体像（23週）

レース日まで **162日＝23週** あります。

| 期 | 期間 | 週数 | 目的 |
|---|---|---|---|
| 準備期 | 2026/9/14 〜 10/18 | 5週 | 走る習慣と、故障しない土台をつくる |
| 第1期 土台 | 10/19 〜 11/15 | 4週 | 距離に体を慣らす |
| 第2期 走力 | 11/16 〜 12/13 | 4週 | 閾値走で「楽に速く」の幅を広げる |
| 第3期 特異 | 12/14 〜 1/17 | 5週 | 目標ペースで長く走る |
| 第4期 仕上げ | 1/18 〜 1/31 | 2週 | 30 km走／3時間走で本番を予行する |
| 調整期 | 2/1 〜 2/21 | 3週 | 量を落とし、疲労を抜いてピークを合わせる |

週ごとの具体的な距離とメニューは [05-plan.md](docs/05-plan.md) にあります。

### 3つの強度（A／B／C）

現在の走力が分からないまま表だけ作っても意味がないので、
プランは3段階を用意しています。**まず [02-goal.md](docs/02-goal.md) の
5 kmタイムトライアルで現在地を測り、そこから選んでください。**

| | 想定目標 | 週の頻度 | ピーク週 | 最長走 |
|---|---|---|---|---|
| **A** | 完走（サブ6） | 週3回 | 36 km | 26 km |
| **B** | サブ5 | 週4回 | 50 km | 30 km |
| **C** | サブ4 | 週5回 | 65 km | 32 km |

## いま何をすべきか（クイックスタート）

1. **今週**：30分続けて走れるか試す（歩いてもいい）→ [02-goal.md](docs/02-goal.md)
2. **2週目以降**：5 km のタイムトライアルで現在地を測り、A／B／C を決める
3. `tracker/index.html` をブラウザで開き、目標タイムとプランを登録する
4. 10/5 の抽選結果を待ちながら、準備期の週3回を淡々とこなす

> **前提の確認**：プランAでも **週3回** が前提です。週1回では6時間の制限時間に
> 届きません。走れる日が週1〜2回しかない場合の落としどころは
> [05-plan.md の「走れる日が週1〜2回しかないとき」](docs/05-plan.md) にあります。

> **最重要**：この計画の失敗要因は「走れないこと」ではなく **「故障すること」** です。
> 40代・デスクワーク中心の体が最初の1か月で壊れるパターンが最も多い。
> 距離は週10%以上増やさない、痛みが出たら即休む。
> 詳細は [08-injury.md](docs/08-injury.md)。

## 記録アプリ

`tracker/index.html` をブラウザで開くだけで動きます。
**ビルド不要・サーバー不要・外部通信ゼロ**（CDNも使わないので、オフラインでも動きます）。

### 使いはじめ方（3通り）

| 方法 | 向き | 手順 |
|---|---|---|
| **端末にファイルを置く** | PCで使う。完全にオフライン | GitHubの「Code → Download ZIP」で落として展開し、`tracker/index.html` をブラウザで開く。**決まった場所に置いてブックマーク**する |
| **Artifactとして公開したものを開く** | スマホでも使う。インストール不要 | 公開済みのURLを開くだけ。ブックマークしておく |
| GitHub Pages | — | このリポジトリは非公開のため、無料プランでは使えない（公開に切り替えれば可） |

**端末間の同期について**

- **公開版（Artifact）** は、開いた端末すべてで同じ記録が見えます。
  PCで取り込めばスマホにも出ます。記録はclaude.ai側に保存されます
  （走行位置は元々読んでいないので含まれません）
- **ファイルとして開いた場合** は、これまでどおりその端末のブラウザ内だけに
  保存され、外部通信はゼロです。移すときは「バックアップ」のJSONを使ってください

- **「今週のメニュー」を自動生成** — その週の7日ぶんを日付・距離・ペース・目安時間つきで表示
- **Googleドライブのフォルダから直接取り込める**（公開版のみ。ファイル操作が要らない）
- **スマートウォッチの `.fit` ファイルをドロップするだけで記録になる**（解析は端末内で完結）
- **取り込んだ記録を開くと詳しい解析が出る** — 1 kmごとのラップ、心拍ゾーンの滞在時間、
  信号待ちなどの停止の検出、心拍ドリフト、その練習が実際には E・M・T・I のどれだったかの判定
- 目標タイムから練習ペース（E／M／T／I）・心拍ゾーン・関門ペースを自動計算
- 日々の練習を距離・時間・主観的強度（RPE）・体調で記録
- 週間距離を計画値と並べてグラフ表示、増やしすぎを警告
- レースまでの日数と「今週やること」を常時表示
- JSON でバックアップ／復元、CSV で書き出し

**記録は端末のブラウザ内にのみ保存され、外部へ送信されません。**
`.fit` ファイルの解析もブラウザ内だけで行われます。

`.fit` の原本は **Googleドライブの「ランニングログ」フォルダ**に保管し、
台帳はそこから取り込んで集計する、という分担です。
詳細は [12-records.md](docs/12-records.md) を参照してください。

## .fit の解析ツール（任意・上級者向け）

**ふだんは要りません。** 同じ解析は台帳（`tracker/index.html`）の記録一覧から、
記録をクリックするだけで見られます。インストールもコマンド操作も不要です。

このツールが役に立つのは、**何本ぶんもまとめて解析したいとき**だけです。
フォルダごと渡せば、中の `.fit` を全部処理して合計も出します。
Node.js 18以降があれば、依存パッケージなしで動きます。

```bash
node tools/fit-report.mjs ~/ランニングログ/Zepp20260912165147.fit --maxhr 190 --goal 5:00:00

# フォルダごと渡すと、まとめて解析して合計も出す
node tools/fit-report.mjs ~/ランニングログ --age 38 --goal 5:00:00
```

| オプション | 内容 |
|---|---|
| `--maxhr` | 最大心拍（実測値）。心拍ゾーンの判定に使う |
| `--age` | 年齢。`--maxhr` が無いとき `208 − 0.7 × 年齢` で推定する |
| `--goal` | 目標タイム（`5:00:00`）。イージーペースの計算に使う |

出るもの：基本情報／1 kmごとのラップ（ペース・心拍・ピッチ）／心拍ゾーンの滞在時間／
心拍ドリフト（前半と後半で、同じ速度に対する心拍がどれだけ上がったか）／
ケイデンスロック（光学式心拍計が歩数を心拍として拾う誤動作）の判定／
その練習が実際には E・M・T・I のどれだったかの判定。
