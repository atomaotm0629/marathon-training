# 12 記録の取り方とデータ仕様

**記録していない練習は、振り返れません。**
この計画は23週あります。12月に「11月に何をしたか」を思い出せる人はいません。

## 記録アプリ

`tracker/index.html` をブラウザで開くだけで動きます。ビルド不要・サーバー不要。

| できること | 内容 |
|---|---|
| 設定 | レース日・目標タイム・プラン強度（A／B／C） |
| ペース表 | 目標タイムから E／M／T／I と関門ペースを自動計算 |
| 本番のペース配分 | 5 kmごとの通過目標（京都の起伏を織り込んだ配分） |
| 練習の記録 | 日付・種別・距離・時間・RPE・心拍・体重・痛み・シューズ・メモ |
| 週間の集計 | 実績と計画を並べたグラフ、週別の距離・平均ペース・最長走 |
| 警告 | 前週比+10%超、痛みの繰り返し、休養日の不足、ロング走の未消化 |
| シューズ管理 | シューズごとの累積距離（500〜700 kmで交換） |
| 書き出し | JSON バックアップ／復元、CSV |
| **.fit の取り込み** | **スマートウォッチのログファイルをドロップすると自動で記録になる** |
| **詳しい解析** | **記録をクリックすると、1 kmごとのラップ・心拍ゾーン・停止・判定が開く** |

### 保存について

**記録はこの端末のブラウザ内（localStorage）にのみ保存され、外部へ送信されません。**

| 注意 | 内容 |
|---|---|
| ブラウザのデータを消すと記録も消える | 定期的にバックアップを |
| 端末・ブラウザごとに別の記録になる | スマホとPCは同期しません |
| プライベートウィンドウでは保存できない | その場合は画面上部に警告が出ます |

**月に1回、「バックアップ」からJSONをコピーして控えを取ってください。**
`records/` に置く場合のファイル名は `backup-2026-12.json` のようにします
（`.gitignore` により、バックアップは誤ってコミットされないようになっています）。

## スマートウォッチのログ（.fit）で管理する

### 全体の流れ

```
走る
 └→ 時計（Amazfit T-Rex 3 ほか）
      └→ Zepp など純正アプリから .fit を書き出す
           └→ Googleドライブ「ランニングログ」フォルダに保存   ← 原本の保管場所
                └→ 台帳の「スマートウォッチから取り込む」にドロップ  ← 集計・警告
```

**Googleドライブが原本、台帳が集計** という分担です。
台帳のデータが消えても、ドライブに .fit が残っていれば全部やり直せます。

### 取り込み方

1. `tracker/index.html` を開く
2. 「スマートウォッチから取り込む」の枠に **.fit ファイルをドロップ**（まとめて複数可）
   - Googleドライブのデスクトップ版を使っているなら、同期フォルダから直接ドロップできます
   - スマホやWeb版なら、いったんダウンロードしてからドロップ
3. 読み取った内容がプレビュー表に出るので、**種別とRPEを指定**する
4. 「チェックした記録を取り込む」を押す

**ファイルはブラウザ内だけで解析され、どこにも送信されません。**
台帳は **ネットワークに一切アクセスしません**（外部のフォントも読み込みません）。
オフラインのまま使えます。

### 取り込まれる項目

| 項目 | FITのどこから |
|---|---|
| 日付・開始時刻 | `session.start_time`（`activity.local_timestamp` との差で現地時刻に直す） |
| 距離 | `session.total_distance` |
| 時間 | `session.total_timer_time` |
| ペース | 距離と時間から計算 |
| 平均心拍 | `session.avg_heart_rate` |
| ピッチ | `session.avg_cadence` × 2（FITは片脚あたりの回転数で持っている） |
| 獲得標高 | `session.total_ascent` |
| 消費カロリー | `session.total_calories` |
| 種別のあたり | `session.sport`（ランは15 km以上ならロング走、それ以外はジョグ） |

**RPE・シューズ・痛み・メモは時計から取れません。** 取り込み時にRPEだけ指定できるので、
覚えているうちに入れてください。シューズと体調のメモは、必要なら別に記録します。

### 重複の扱い

同じファイル名、または「同じ日付・距離の差0.1 km以内・時間の差60秒以内」の記録が
すでにある場合は **「取込済」と表示され、既定でチェックが外れます。**
ドライブのフォルダを丸ごと何度ドロップしても、二重登録にはなりません。

### ドライブから台帳へ、手数を減らす

`.fit` は Googleドライブに貯まりますが、台帳（ブラウザ）は**外部と通信しない設計**なので、
ドライブから直接は読めません。手数を減らす方法は次のとおりです。

| 方法 | 手数 | 備考 |
|---|---|---|
| **Googleドライブ デスクトップ版（無料）を入れる** | **ドラッグ&ドロップ1回** | 同期フォルダがPCのローカルフォルダとして見えるので、そこから台帳へ直接ドロップできる。**いちばん現実的** |
| スマホ／Web版からダウンロード | ダウンロード → ドロップ | 端末にファイルを落としてから |
| 台帳にDrive APIを組み込む | — | **やめた方がよい。** Google Cloudでのクライアント登録が要り、`file://` では動かず（httpsのオリジンが必要）、何より「外部通信ゼロ」が崩れる |

### 詳しい解析は、記録をクリックすると開きます

`.fit` から取り込んだ記録には **「▼ 詳しく」** が付きます。クリックすると、
その練習の中身が開きます。

| 出るもの | 内容 |
|---|---|
| 停止と移動のみのペース | 信号待ちなどを除いた、本当に走っていたペース |
| 1 kmごと | ラップ・心拍・ピッチ・停止秒数。Eの上限を超えた心拍は色がつく |
| 心拍ゾーンの滞在時間 | E／M／T／I に何%ずついたか。**80/20が守れているかはここで分かる** |
| 停止の一覧 | 地点・秒数・その間の心拍。信号区間と本当の失速を切り分けられる |
| 心拍ドリフト | 前半と後半で、同じ速度に対する心拍がどれだけ変わったか |
| 判定 | その練習が実際には E・M・T・I のどれだったか |

**心拍ゾーンは、設定の「最大心拍」を変えると計算し直されます。**
取り込んだときの数字が固定されるわけではありません
（1拍ごとの滞在秒数を保存してあるため）。

1本ぶんの解析はこれで足ります。**何本もまとめて解析したいときだけ**、
`tools/fit-report.mjs`（Node.js が必要）を使ってください。

### GPXは要りません

**.fit だけ保存すれば十分です。** 理由は3つ。

| | |
|---|---|
| 情報量 | GPXは基本的に「位置と時刻」。心拍・ピッチ・ストライド・獲得標高・消費カロリー・ラップは、FITにしか入っていません |
| 重複 | GPXに入る情報はFITの部分集合です。両方持つ意味がない |
| 安全 | GPXは走行経路がそのまま読める形式です。**自宅の位置が特定できる**ので、コピーは増やさないに越したことはありません |

台帳が読むのは FIT の `session`（走行のまとめ）と `activity`（時差）だけで、
**位置情報のレコードには触れません。**

コースを地図で振り返りたいときは、Zeppアプリ側の地図表示で足ります。
どうしてもGPXが要る場面（別サービスへの移行など）が来たら、そのとき書き出せば十分です。

### ファイル名

Zeppの書き出しは `Zepp20260912165147.fit`（＝2026/09/12 16:51:47 開始）の形式で、
そのまま並べれば時系列になります。**リネームせずにそのまま置いてください。**
台帳は重複判定にファイル名も使います。

## 記録する項目

| 項目 | 必須 | 内容 |
|---|---|---|
| 日付 | ○ | |
| 種別 | ○ | 下表のいずれか |
| 距離（km） | 走る種別は○ | 小数点以下2桁まで |
| 時間 | — | `1:05:30`／`45:30`／`45`（分のみ）のいずれの書式でも可 |
| RPE | 推奨 | 主観的強度 1〜10（[04-paces.md](04-paces.md)） |
| 平均心拍 | 任意 | 時計がある場合 |
| 体重 | 任意 | 朝いちに測った値。日々の増減ではなく週平均の推移を見る |
| 痛み | ○ | なし／違和感／痛みあり |
| シューズ | 推奨 | 累積距離の管理に使われる |
| メモ | 推奨 | コース・天候・体調・気づいたこと |
| ピッチ（spm） | 自動 | .fit から取り込んだ場合のみ |
| 獲得標高（m） | 自動 | 同上。京都のコース対策の目安になる |
| 消費カロリー | 自動 | 同上 |

### 種別

| 記号 | 種別 | 距離を合算 |
|---|---|---|
| E | ジョグ（E） | ○ |
| L | ロング走 | ○ |
| M | ペース走（M） | ○ |
| T | 閾値走（T） | ○ |
| I | インターバル | ○ |
| R | レース・タイムトライアル | ○ |
| X | クロス（自転車・水泳・歩行） | — |
| S | 補強 | — |

クロスと補強は週間走行距離には合算されませんが、**記録は残ります。**
走れない日に何をしたかを残しておくと、後から振り返るときに効きます。

## RPEを必ず入れる理由

距離とペースだけでは、**疲労が溜まっているかどうかが分かりません。**

```
11/10  10.0 km  1:25:00  8'30"/km  RPE 4   ← 順調
12/08  10.0 km  1:25:00  8'30"/km  RPE 7   ← 同じ練習が「きつい」= 疲労
```

**同じペースでRPEが2以上上がった状態が続いたら、回復週を前倒しします。**
これは数字がないと絶対に気づけません。

## CSV の仕様

「CSV」ボタンで、以下の列を持つCSVが表示されます。コピーして `records/` に保存してください。

| 列 | 内容 |
|---|---|
| `date` | 日付（YYYY-MM-DD） |
| `type` | 種別の記号（E／L／M／T／I／R／X／S） |
| `type_name` | 種別の名前 |
| `dist_km` | 距離（km） |
| `time_sec` | 時間（秒） |
| `time` | 時間（h:mm:ss） |
| `pace_per_km` | 1 kmあたりのペース（m:ss） |
| `rpe` | 主観的強度 1〜10 |
| `hr` | 平均心拍 |
| `cadence_spm` | ピッチ（1分あたりの歩数） |
| `ascent_m` | 獲得標高（m） |
| `kcal` | 消費カロリー |
| `weight` | 体重（kg） |
| `pain` | 0＝なし／1＝違和感／2＝痛みあり |
| `shoe` | シューズ名 |
| `source` | `fit`＝時計から取り込み、空欄＝手入力 |
| `file` | 取り込み元の .fit ファイル名 |
| `memo` | メモ |

テンプレートは [../records/template.csv](../records/template.csv) にあります。
表計算ソフトで直接つけたい場合はこちらを使ってください。

## JSON の構造（バックアップの中身）

```json
{
  "cfg": {
    "raceDate": "2027-02-21",
    "goal": 18000,
    "tier": "B"
  },
  "logs": [
    {
      "lid": "l1a2b3c4",
      "date": "2026-09-14",
      "type": "E",
      "dist": 6.2,
      "sec": 2160,
      "rpe": 4,
      "hr": 168,
      "cad": 164,
      "asc": 27,
      "kcal": 949,
      "wt": 70.2,
      "pain": 0,
      "shoe": "デイリー",
      "src": "fit",
      "file": "Zepp20260912165147.fit",
      "memo": "河川敷"
    }
  ]
}
```

| フィールド | 内容 |
|---|---|
| `cfg.goal` | 目標タイム（秒）。18000 = 5時間 |
| `cfg.tier` | プラン強度 `"A"` / `"B"` / `"C"` |
| `logs[].lid` | 記録の一意なID（自動生成） |
| `logs[].sec` | 所要時間（秒） |
| `logs[].cad` | ピッチ（spm） |
| `logs[].asc` | 獲得標高（m） |
| `logs[].pain` | 0／1／2 |
| `logs[].src` | `"fit"`＝時計から取り込み |
| `logs[].file` | 取り込み元の .fit ファイル名（重複判定に使う） |

**この形式で貼り付ければ、別の端末に復元できます。**

## 振り返りのタイミング

| いつ | 見るもの |
|---|---|
| 走った日 | .fit をドライブに保存（時計から書き出すだけ） |
| 毎週日曜の夜 | 週ぶんの .fit を台帳に取り込む。週の合計距離と計画の差、ロング走が消化できたか |
| 回復週（W4・W8・W11・W14） | 直近4週のRPEの推移、痛みの記録、体重の推移 |
| 5 kmTTの後（P3・W8・W14） | タイムの変化。目標タイムを見直す |
| W15の予行ロング走の後 | 補給・装備の問題点を全部メモに書き出す |
| **レース後** | 5 kmごとのラップと計画の差、失速地点、次に変えること |

**週1回、5分でいい。** 見ないで溜めるだけの記録は、記録ではありません。
